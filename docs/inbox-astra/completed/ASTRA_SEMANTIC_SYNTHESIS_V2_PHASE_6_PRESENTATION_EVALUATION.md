# Astra Semantic Synthesis V2 Phase 6 Presentation Evaluation

## Scope

Phase 6 starts from the approved Phase 5.1 claim-planned baseline. The rejected
Phase 5.2 operation-reconciliation prompt is research only and is not restored.
This phase compares presentation without changing the `@astra/astrology`
facade, calculation authority, evidence selection, prose, report contracts,
routes, persistence, or customer-facing headings.

The private comparison uses the accepted Cheyenne Deep Phase 5.1 report and
selected-evidence packet. Tony is not regenerated or used as a new control.
There are no model calls and no report generations.

## Hypothesis

Changing primary heading vocabulary will not improve comprehension enough to
justify losing familiar navigation. A short atomic evidence subtitle may add
orientation and perceived specificity while preserving stable headings and
fixed order.

## Variants

1. Current headings and fixed order.
2. Candidate functional headings and fixed order.
3. Current headings, fixed order, and atomic evidence subtitles.
4. Candidate functional headings, confidence-ranked flexible order after
   Identity, and atomic evidence subtitles.

Every variant preserves the original chapter keys and prose byte-for-byte.
Subtitles may use only a direct selected chart fact plus the chapter's bounded
focus. Evidence-graph traversal, aggregate dispositor chains, unrelated
signals, provenance plumbing, biography, timing, skill, causal mechanism, and
another person's state are prohibited.

## Decision

**GO for Phase 6 evaluation.**

Keep the current stable chapter headings and fixed Deep order. The candidate
functional set is not clearer enough to replace familiar navigation:
`Core Orientation` conflicts with the Core tier name, several labels are more
abstract, and `Perception & Distortion` adds avoidable pathologizing tone.
Confidence-ranked flexible order creates substantial movement and groups
reused roots without a demonstrated comprehension benefit.

For a separately approved customer-facing presentation change, test one short
optional Deep subtitle built from a direct selected chart fact plus the bounded
chapter focus. Omit the subtitle when no safe atomic fact exists. Do not change
chapter keys, order, evidence selection, prose, contracts, or the
`@astra/astrology` facade.

## Approved implementation — 2026-07-27

The product owner approved the recommended subtitle treatment. The existing
report reader now renders optional Deep subtitles from its already selected
section evidence. The helper accepts only one direct atomic placement or aspect
fact; evidence containing dispositor, rulership, graph, provenance,
configuration, or other traversal terms is omitted. Current chapter headings,
order, keys, report prose, selected evidence, calculation authority, routes,
schema, persistence, public contracts, and the `@astra/astrology` facade remain
unchanged.

The same subtitle is included in the existing copy/download Markdown, so the
rendered and exported presentation agree. A deterministic subtitle suite proves
that Deep-only gating, direct-fact selection, and unsafe-evidence omission hold.
All inherited Phase 0–6 and production gates passed. Browser QA confirmed the
Library-to-Deep-report journey at desktop, tablet, and mobile with nine
subtitles, unchanged headings/order/prose, no horizontal overflow, and zero
console/page errors. No model call, report generation, or Tony regeneration
occurred.
