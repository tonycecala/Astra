# Alpha pilots should stay reversible and narrow

## What Happened
When an alpha request is a simple optional path, do not introduce durable offer catalogs, redemption tracking, account-wide eligibility, or historical display machinery unless the product explicitly needs them. Prefer a server-validated per-request flag, a small UI control placed at the decision point, explicit telemetry, and focused end-to-end proof. If an exploratory schema change has already reached a shared development database, add a cleanup migration rather than pretending it never happened. This keeps pilots understandable, reversible, and cheap to remove or expand.
